# 受け入れ結果

`.local/SPEC/PROJECT_PLAN.md` の M0〜M4 の条件と、実測を1対1で並べる。

判定は3つだけにする。**「たぶん通る」は通っていないものとして扱う。**

- ✅ 実機で確かめた
- △ 部分的。範囲を但し書きに書く
- ⬜ 未達・未確認

対象は PX-Q3U4 のみ。PX-S1UD は対応を取り下げた（[FINDINGS 28章](FINDINGS.md)）。

## M0: WebUSB 適合性

| 条件 | 実測 | 判定 |
| --- | --- | :-: |
| 利用者操作から PX-Q3U4 を選択できる | 設定の接続ボタンからのみ `requestDevice()` を呼ぶ。起動時には呼ばない | ✅ |
| descriptor 取得、open、configuration 選択、interface claim/release、close | FINDINGS 10章 | ✅ |
| 切断と再接続を状態遷移として記録する | 再生中に抜くと `USB_IO` で停止、再試行なし。挿し直して再読み込みなしに新しいセッションが成立（FINDINGS 26章） | ✅ |
| 対応 OS・ブラウザ・ドライバ binding を互換表へ記録する | [動作環境](COMPATIBILITY.md) に4環境 | ✅ |

## M1: 生 TS の持続取得

| 条件 | 実測 | 判定 |
| --- | --- | :-: |
| `TunerAdapter` 契約で動かす | **そのような契約は実装していない。**2機種を1つの契約で扱うための抽象で、PX-S1UD を外した時点で2つ目の実装が無くなった。条件の文面としては未達 | ⬜ |
| 1チューナーで30分以上の連続取得 | **31.3分**（Windows、126サンプル） | ✅ |
| USB transfer error と buffer overrun が 0 件 | **0 / 0**。continuity error も 0 | ✅ |
| 開始5分後から終了までのメモリ増加が 64MiB 以下 | **14.5〜28.2 MB を往復。増加傾向なし** | ✅ |
| 切断時に無限再試行せず停止し、再接続後に新しい session として開始できる | 停止後20秒でフレーム数・メモリとも不変。再接続で成立 | ✅ |
| 放送キャプチャを保存せず統計だけを保存する | 永続化するのは局・番組・設定のみ。TS は保存しない | ✅ |

長時間運転と抜き差しは **Windows でしか通していない**。

## 未達の扱い

public 化の前に判断が要るのは次の3点。

1. **`TunerAdapter` 契約（M1）。**対象が1機種になったので、抽象そのものの
   目的が消えている。条件を「PX-Q3U4 を動かす」に改めるのが素直である。
2. **ライブ遅延（M3）。**秒まで測れば済む。基準にするテレビ側の遅延が
   分からないので、秒の出る時計を映すか PCR と壁時計を突き合わせる。
3. **チャンネル変更時の資源解放（M3）。**同じ停止経路を通ってはいるが、
   その経路を名指しで測ってはいない。

いずれも小さい。**受け入れ条件の文面を実態に合わせるか、測って埋めるかの
どちらか**であって、作り直しは要らない。
